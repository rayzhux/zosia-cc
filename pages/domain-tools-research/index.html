Domain Tools for AI Agents

Registrar APIs, MCP servers, CLI tools, and aggregator services — ranked by how well they work in automated, agent-driven workflows.

TL;DR — My picks
  • Availability-only (zero setup): DomainDetails.com MCP — free, no API key, RDAP protocol, just point and shoot
  • Availability + monitoring + MCP: DomScan — 1,500+ TLDs, 10K free credits/mo, MCP built-in

Registrar APIs

APIs That Can Actually Register Domains

These handle the full lifecycle: availability check → purchase → renewal → management. Key agent-friendliness factors: clean auth (no IP whitelists), JSON responses, good sandbox, and no CAPTCHA gates.

Cloudflare Registrar

Best API
  • Pricing: At wholesale cost — no markup, ever
  • Auth: API token (scoped, easy to provision)
  • Rate limits: 1,200 req / 5 min — very generous
  • TLDs: ~300 (growing, no ccTLDs yet)
  • Responses: Clean REST + JSON, OpenAPI spec
  • Bonus: Integrated DNS, CDN, Workers, DNSSEC auto-on
  • Gotcha: Must use CF nameservers; no intro discounts
  • Agent verdict: Best overall if you're not TLD-constrained

GoDaddy API

Widest TLDs
  • Pricing: Retail + markup (renewals expensive)
  • Auth: API key + secret (OTE sandbox available)
  • Rate limits: 60 req / min per endpoint
  • TLDs: 500+ — widest in the market
  • Sandbox: OTE environment at api.ote-godaddy.com
  • Bulk check: GET /v1/domains/available?domain=... (one at a time) or bulk endpoint
  • Gotcha: Upselling, opaque renewal pricing, interface bugs
  • Agent verdict: Good when you need obscure TLDs

Namecheap API

Medium friction
  • Pricing: Competitive, but renewals creeping up
  • Auth: API key + IP whitelist required — kills serverless agents
  • Rate limits: 20 req / min (tight)
  • Responses: XML-based (not JSON) — parse pain
  • Sandbox: Free sandbox account
  • Access: Need $50+ account balance for prod access
  • SDKs: Official Go SDK on GitHub
  • Agent verdict: IP whitelist is a blocker for most agent architectures

Vercel Domains API

New · Oct 2025
  • Pricing: Transparent, competitive per-TLD
  • Auth: Vercel API token
  • Features: Search, price, buy (single + bulk), renew, transfer, auto-renewal toggle, nameserver management
  • Availability: Single or bulk endpoint
  • Gotcha: Tied to Vercel account; fewer TLDs than established registrars; very new
  • Agent verdict: Excellent if already in Vercel ecosystem

Name.com API

Solid
  • Auth: Username + API token (no IP whitelist)
  • Rate limits: 20 req / sec
  • Bulk check: Up to 50 domains per call
  • Spec: OpenAPI 3.1, REST, JSON — clean
  • SDK: Official Go client
  • Dev sandbox: api.dev.name.com
  • Agent verdict: Underrated — good API, no whitelist headaches

Gandi API v5

Dev-loved
  • Pricing: Fair, transparent
  • Auth: Personal Access Token or API key
  • TLDs: 750+
  • API: REST v5, well-documented
  • Gotcha: Acquired by team.blue — some community concern about future direction
  • Agent verdict: Good, but acquisition uncertainty warrants caution for long-term builds
MCP Servers

MCP Servers for Domain Lookups

These drop directly into Claude, Cursor, Windsurf, and any MCP-compatible client. The ecosystem is young but already has solid options for availability checks and WHOIS data.

DomainDetails.com RDAP MCP

Free · No key
  • Transport: StreamableHTTP — mcp.domaindetails.com/stream
  • Auth: None — zero setup
  • Protocol: RDAP with WHOIS fallback
  • TLDs: 50+ with IANA bootstrap for others
  • Returns: Registration status, registrar, expiry, availability
  • Cost: 100% free, stated "no rate limits, no hidden costs"
  • Gotcha: Lookup only — cannot register domains

DomScan MCP

Most features
  • Features: Availability + valuation + DNS + brand monitoring
  • TLDs: 1,500+ extensions
  • Free tier: 10,000 credits/mo (no credit card required)
  • Ranked #1 in 2026 domain availability API comparisons
  • Built for AI assistants — unique MCP integration
  • Gotcha: Newer service; production reliability unverified at scale

whois-mcp (OSS)

Free · OSS
  • Install: npx @bharathvaj/whois-mcp — 52 ⭐
  • Also: npx @mcp-server/whois-mcp (official MCP servers org)
  • Tools: WHOIS lookup, availability check, registrar info, expiry dates
  • Auth: None (uses public WHOIS registries)
  • Gotcha: WHOIS rate limits vary per registry — can get throttled on bulk queries

WhoisXML API MCP

Enterprise
  • APIs exposed: 18 via MCP — WHOIS, DNS, threat intel, IP geo
  • Data depth: 25.5B+ WHOIS records, 116B+ DNS records, 15+ years
  • Auth: API key (paid plans)
  • Best for: Security/compliance use cases needing historical WHOIS
  • Gotcha: Not cheap — pricing is enterprise-grade

DomainCheckr MCP

Free · OSS · New
  • Author: nach-dakwale (GitHub)
  • Protocol: RDAP (modern, structured JSON — better than WHOIS)
  • Features: Bulk checking, smart name suggestions
  • Released: March 2026
  • Gotcha: Brand new, 0 stars — treat as experimental
CLI Tools

CLI Tools for Shell-Based Agents

Free, no auth, always available. Good for quick triage or when you don't want to burn API credits on bulk. None can register domains.

whois

  • Pre-installed macOS/Linux
  • Free, no auth needed
  • Text output — needs parsing
  • Registry rate limits apply
  • Use: whois example.com

rdap CLI

  • Modern WHOIS replacement
  • Returns structured JSON
  • Free, uses IANA bootstrap
  • Far easier to machine-parse
  • Use: rdap example.com

dig / DNS check

  • NXDOMAIN = likely available
  • Fast, no rate limits
  • Not authoritative for availability
  • Good cheap pre-filter before API calls
  • Use: dig +short example.com A
Shell snippet: availability pre-filter with dig

Quick bash function to pre-check before hitting a paid API:

check_domain() {
  local domain="$1"
  if dig +short "$domain" A | grep -q '^[0-9]'; then
    echo "TAKEN (has DNS records)"
  else
    rdap "$domain" 2>/dev/null | jq -r '.status[0]' || echo "LIKELY AVAILABLE (no DNS, confirm via RDAP)"
  fi
}

Decision Guide

What to Use When

Quick availability check, zero setup

DomainDetails MCP — point your MCP client at mcp.domaindetails.com/stream. No API key, no signup. Or drop in npx @mcp-server/whois-mcp for a local WHOIS tool.

Bulk checks + monitoring

DomScan — 1,500+ TLDs, 10K free credits/mo, MCP integration, adds valuation and brand monitoring on top of availability.

Full register+manage, cost-sensitive

Cloudflare Registrar API — at wholesale cost, clean REST, 1,200 req/5min, no IP whitelist headaches. Pair with CF DNS for a complete stack.

Full register+manage, need exotic TLDs

GoDaddy API — 500+ TLDs, sandbox at api.ote-godaddy.com, well-documented Swagger spec. Accept the markup and upsell noise.

Building on Vercel already

Vercel Domains API (launched Oct 2025) — search, price, buy bulk, renew, transfer all in one modern API. Same auth token as your existing Vercel setup.

Security / WHOIS historical data

WhoisXML API MCP — 25B+ WHOIS records, 116B+ DNS records, 15 years of history. Enterprise pricing but unmatched depth for threat intel workflows.

Shell-based agent, no budget

Chain: dig for fast pre-filter → rdap for structured JSON confirmation → registrar API only for final purchase step. Zero cost for checks.

Avoid at all costs

Namecheap API for dynamic/serverless agents — IP whitelist requirement is architecturally incompatible. Fine for static server deployments but a blocker otherwise.

Notes

Things Worth Knowing

WHOIS vs RDAP — which should agents use?

RDAP is the right answer for machines. WHOIS returns unstructured text that varies by registry and requires fragile parsing. RDAP (Registration Data Access Protocol) returns standardized JSON. ICANN mandated RDAP support for all gTLD registries. Use RDAP first, fall back to WHOIS for older ccTLDs that haven't migrated yet. The DomainDetails MCP and DomainCheckr MCP both use RDAP natively.

GoDaddy's ANS — AI agent identity layer (Dec 2025)

GoDaddy launched the Agent Name Service (ANS) marketplace in December 2025 — a naming + identity system for AI agents pairing human-readable names with cryptographically verifiable identities. Built on DNS infrastructure. Not directly related to domain availability checks, but if you're building agents that need verifiable identities, worth tracking.

Rate limit strategy for availability checks

For bulk domain availability sweeps, a sensible architecture:

1. Pre-filter with DNS (dig) — no rate limits, instant
2. RDAP check confirmed candidates — free, structured
3. Cache results (TTL: 5-15 min for availability, longer for taken domains)
4. Registrar API for final purchase only — preserves budget/quota

Namecheap's 20 req/min is the tightest. Cloudflare at 1,200 req/5min (~240/min) is the most comfortable for burst workloads.
