Slack's AI Landscape (March 2026)

Two Paths: Traditional Bot vs. Agent-First

Slack now has two fundamentally different approaches. Here's the honest comparison:

Dimension Traditional Bot (Socket Mode) Agent-First (Agents & AI Apps)
Setup Moderate — bot token + app token, Socket Mode, done Higher — enable Agents feature, wire assistant scopes, implement lifecycle APIs
UI Bot appears as channel member. Messages in threads/channels. Dedicated top-bar entry + split-view conversational UI. Feels native.
Streaming Post → update loop (chat.postMessage → chat.update) Native streaming via assistant.* methods + chat.startStream/appendStream
Context Only sees channels it's invited to. Manual context retrieval. Real-time Search API + MCP for permission-aware RAG across workspace
Thread mgmt Manual — you handle thread_ts assistant.threads.* — loading states, suggested prompts, thread titles built-in
OpenClaw support Ready now Socket Mode plugin works out of the box Not yet Would need OpenClaw plugin changes for assistant.* APIs
Best for Personal assistant like Zosia — quick, works today Enterprise AI products shipping to Slack Marketplace
My recommendation Start with the traditional bot + Socket Mode. It's what OpenClaw's Slack plugin already supports, it works exactly like our Discord setup (read messages, respond in threads, react, stream), and you can be live in 10 minutes. The Agent-first stuff is cool but it's enterprise Agentforce territory — overkill for a personal assistant.
03

What's New in Slack (2025–2026)

Feb 2026 MCP Server

Slack released an official Model Context Protocol server. Lets LLMs discover Slack tools, query workspace context with permission-aware access. JSON-RPC based. Think of it as "Slack as an MCP tool provider."

Feb 2026 Real-time Search API

Query-based, permission-respecting search across Slack messages, files, channels. For RAG workflows. Requires search:read.* scopes. Better than bulk-exporting messages.

2025 Assistants API

Beta assistant integration — but Slack is sunsetting it in favor of MCP + assistant.* methods. Don't build on this.

2025 Native Streaming

chat.startStream / appendStream / stopStream — real token-by-token streaming in Slack messages. OpenClaw already supports this (nativeStreaming: true in your config).

Retired Workflow Steps from Apps

Legacy "Steps from Apps" is dead (Sept 2024). Replaced by custom functions on Slack's Deno platform. Not relevant for our use case.

Ongoing Agentforce / AI Agents

Salesforce-powered agents in Slack (HR/IT/Service). Enterprise play. Third-party AI apps can integrate via assistant APIs. Not what we need for Zosia.

Setup Plan

Quick Start — 10 Minutes to Live

Here's what we need to do, in order:

Step 1. Go to api.slack.com/apps → Create New App → From scratch

Name it "Zosia" (or whatever), install to raymondos.slack.com

↓

Step 2. Enable Socket Mode (Settings → Socket Mode → Enable)

This generates an App-Level Token (xapp-...). Copy it.

↓

Step 3. Configure bot scopes (OAuth & Permissions):

app_mentions:read channels:history channels:read chat:write groups:history groups:read im:history im:read im:write mpim:history reactions:read reactions:write users:read

↓

Step 4. Subscribe to events (Event Subscriptions → Subscribe to bot events):

app_mention message.channels message.groups message.im message.mpim reaction_added

↓

Step 5. Install app to workspace → Copy the Bot Token (xoxb-...)

↓

Step 6. Add tokens to ~/.openclaw/.env:

SLACK_BOT_TOKEN=xoxb-your-bot-token
SLACK_APP_TOKEN=xapp-your-app-token
↓

Step 7. Update OpenClaw config — add bot/app tokens to channels.slack:

botToken: "${SLACK_BOT_TOKEN}"
appToken: "${SLACK_APP_TOKEN}"

Then gateway restart — Zosia goes live in Slack.
