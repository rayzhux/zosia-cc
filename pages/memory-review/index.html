The Big Picture

Memory is a three-stage pipeline

Every conversation flows through three stages: creation (automatic), distillation (nightly cron), and recall (QMD search). Each stage has different actors and different failure modes.

Stage 1 — Creation (automatic)

OpenClaw's session-memory hook fires on every /new and /reset. It captures the last 30 messages and writes a summary to memory/YYYY-MM-DD-slug.md. I also manually write daily notes (YYYY-MM-DD.md) when something important happens.

Stage 2 — Distillation (nightly cron, 02:00 Dubai)

A cron job reads all un-distilled daily + session files, filters for durable knowledge (lessons, project changes, tech setup changes, corrections), and surgically promotes the good stuff into MEMORY.md (top-level, always loaded) and topic files (detailed reference). Garbage gets skipped.

Stage 3 — Recall (QMD search, on demand)

When I need past context, QMD runs three local AI models on your M2 GPU: keyword search (BM25), semantic vector search, and a reranker. Results from all three merge into the top 8 snippets that get injected into my context.

The Distillation Pipeline

Nightly cron: 02:00 Dubai (22:00 UTC)

A Codex-powered cron job reads all un-distilled files, applies strict criteria to separate signal from noise, and surgically promotes durable knowledge into MEMORY.md and topic files.

1. Pre-process

Python script checks marker file (.last-distilled), identifies all files since last run, classifies them as normal/low/skip priority. Handles multi-day catch-up automatically.

2. Distill

Reads criteria.md (what's durable vs garbage). Reads all normal-priority files in full. Scans low-priority headers. Makes surgical edits — never rewrites whole files. Promotes in two steps: detail → topic file, one-liner → MEMORY.md.

3. Validate

Python script checks MEMORY.md stays under 80 lines, topic files under their budgets, no structural damage. Pass/warn/fail.

4. Mark Done

Updates .last-distilled marker so next run starts from the right date.

5. Report

Posts summary to Discord #system: files processed, promotions made, garbage skipped.

QMD Search — The Recall Engine

Three AI models running on your Mac's GPU

QMD 1.1.5 runs locally on your M2's Metal GPU. No data leaves your machine for memory search.

  • Embedding Model embeddinggemma-300M
    Converts text into 256-dim vectors. Used for semantic similarity search — "Singapore server" matches "Charlie VPS" even with no shared keywords.
  • Query Expansion Model qmd-query-expansion-1.7B
    Takes your search and generates keyword (lex), semantic (vec), and hypothetical answer (hyde) variants. Broadens recall without losing precision.
  • Reranking Model Qwen3-Reranker-0.6B
    Reads each candidate result against your query and re-scores them. Catches nuance that keyword + vector alone miss. Fixed in 1.1.1 to handle long docs properly.

Search flow: query → two paths → rerank → results

Every memory_search call triggers this pipeline (~10-16 seconds):

1. Query Expansion

Your search text gets expanded into multiple forms: keyword variants, semantic rephrasing, hypothetical answer passages.

2. Dual Search (parallel)

BM25 keyword matching runs on the text index. Vector similarity runs on the embedding index. Both return candidate lists.

3. Reciprocal Rank Fusion

Both candidate lists are merged using RRF scoring — files that appear in both lists get boosted.

4. Rerank

Top candidates are deeply scored by the reranker model. Reads each snippet against your query for semantic relevance.

5. Return top 8

Best snippets returned with file path + line numbers. Injected into session context.
