Recommendations · WAG

Stopping one write loop removes about $850 a month.

  1. Stop the dealrevs-demo write loop

    Find out what writes about 30M rows a day to dealrevs-demo: a cron, a queue consumer on dealrevs-demo-jobs, or the autodata sync. Make the job incremental (upserts that only touch rows that changed), or stop running it against the demo copy. A demo does not need live data refreshed every few minutes.

    saves~$850/mo

  2. Add indexes and stop full scans

    About 113k rows are read per query. Run EXPLAIN QUERY PLAN on the hot queries and add indexes on the filter and join columns. This also cuts the CPU time per request.

    saves~$50/mo

  3. Point the demo at shared reference data

    dealrevs and dealrevs-demo duplicate the whole stack: D1, queues, DOs and R2. If the demo has to sync, sync a small snapshot once a day.

    preventsdoubled cost

  4. Set usage alerts

    Add Billing notifications for usage-based charges (for example at $25 and $100) so the next spike shows up within a day.

    guardrail

  5. Cache worldauto-group-site

    85 ms of CPU per page view on a static site: serve it through Workers Static Assets or the cache API.

    efficiency

  6. Grant Billing Read to verify

    Add Billing:Read to the WAG connector so invoices and subscriptions can be checked line by line against these estimates.

    verify
