Release audit • OpenClaw v2026.4.5

Not just a feature drop,
a platform refactor with media muscles.

I reviewed the code delta from v2026.4.2 to v2026.4.5. The loud story is new media generation and multilingual UI. The real story is deeper: OpenClaw is moving toward a cleaner plugin-owned runtime, tighter prompt-cache discipline, and more structured agent execution.

Compared tags: v2026.4.2 → v2026.4.5 Diff scope: 5,746 files changed 331,486 insertions 268,299 deletions

Executive read

v2026.4.5 makes OpenClaw feel less like a chat wrapper around tools and more like an agent operating system. Media generation, approval delivery, plugin-owned reply routing, memory promotion, and control-plane UX all got upgraded in the same sweep.

Plugin and runtime ownership got a lot cleaner.
That matters more than any single user-facing feature, because it lowers future friction across channels, providers, and ACP integrations.

Major updates

1 • Media generation

Music and video generation became real first-class tools

OpenClaw now has built-in music_generate and video_generate tools with proper schemas, provider routing, async task tracking, duplicate guards, and completion wake delivery. This is not a hacky wrapper, it is integrated runtime surface area.

  • Music tool supports prompt, lyrics, instrumental mode, ref images, duration hints, format selection.
  • Video tool supports images, videos, resolution, aspect ratio, duration, audio, watermark.
  • Comfy is now a bundled workflow plugin spanning image, music, and video generation.
Evidence: src/agents/tools/music-generate-tool.ts · src/agents/tools/video-generate-tool.ts · extensions/comfy/openclaw.plugin.json
2 • Agent runtime

Agent execution got more structured and less messy

The runtime now has a formal update_plan tool, stronger separation between structured tool definitions and prompt prose, and explicit prompt-cache boundary machinery. That means long runs can be shown cleanly and cached more reliably.

  • update_plan validates ordered steps and one active step.
  • System prompt now treats structured tool definitions as the source of truth.
  • Dynamic prompt sections can be pushed below a cache boundary.
Evidence: src/agents/tools/update-plan-tool.ts · src/agents/system-prompt.ts · src/agents/system-prompt-cache-boundary.ts
3 • Plugin architecture

More behavior moved out of core and into plugin-owned runtime seams

This release keeps pushing core logic toward registries, hooks, and plugin-owned surfaces. ACP runtime helpers are exposed through the plugin SDK, and reply interception is formalized through reply_dispatch hook handling.

  • Bundled ACP runtime is directly exposed to plugins.
  • Reply dispatch is a first-class hook, not a hardcoded special case.
  • Plugin activation state is now explicit about source: disabled, explicit, auto, default.
Evidence: src/plugin-sdk/acp-runtime.ts · src/plugins/wired-hooks-reply-dispatch.test.ts · src/plugins/config-policy.ts
4 • Memory

Dreaming matured from vague idea to configurable subsystem

Memory promotion is now clearly modeled as three phases with defaults for cadence, score thresholds, recovery behavior, aging, and storage mode. Bedrock embeddings support also landed, which broadens memory backend options without bespoke glue.

  • Light, deep, and REM phases each have separate config.
  • Deep dreaming has recency half-life and max-age controls.
  • Bedrock embedding support includes Titan, Cohere, Nova, and TwelveLabs model families.
Evidence: src/memory-host-sdk/dreaming.ts · packages/memory-host-sdk/src/host/embeddings-bedrock.ts
5 • Control UI

Control UI got much closer to an actual product

The UI now ships many more locales and adds live ClawHub search, detail, and install flows in the Skills panel. That is a meaningful jump in operator usability, not cosmetic fluff.

  • Skills view includes registry search and install UX.
  • Gateway handlers back skills.search, skills.detail, and ClawHub installs.
  • New localized bundles include Ukrainian and many others.
Evidence: ui/src/ui/views/skills.ts · ui/src/ui/controllers/skills.ts · src/gateway/server-methods/skills.ts · ui/src/i18n/locales/uk.ts
6 • Safety and delivery

Operator safety got better without making the system feel more bureaucratic

Native iOS exec approval push delivery and configurable context visibility are both here. One improves response time for approvals, the other reduces accidental context oversharing across channels.

  • APNs approval pushes target operator-scoped iOS devices.
  • contextVisibility can now resolve per channel, per account, and default fallback.
  • The release also contains a lot of fail-closed cleanup around auth, hooks, and config migration.
Evidence: src/gateway/exec-approval-ios-push.ts · src/config/context-visibility.ts

What changed under the hood

The release is opinionated about ownership. Core keeps shrinking its direct knowledge of providers, channels, ACP, and dispatch behavior. More of that is moving into registries, plugin SDK seams, activation policy, and typed tool surfaces. That is exactly what you do before a platform starts scaling cleanly.

Prompt-cache discipline is now intentional

The code is no longer treating prompt reuse as luck. There is explicit cache-boundary splitting, structured prompt normalization, and prompt-cache observability with diffed causes like model changes, system prompt changes, transport changes, and tool-set changes.

Evidence: src/agents/prompt-cache-stability.ts · src/agents/pi-embedded-runner/prompt-cache-observability.ts

Plugin activation policy got more legible

resolvePluginActivationState now names activation sources directly: disabled, explicit, auto, default. That sounds minor. It is not. Debugging plugin state gets dramatically easier once enablement is explainable.

Evidence: src/plugins/config-policy.ts
Net effect: the user-facing features in v2026.4.5 are nice, but the deeper win is that OpenClaw is becoming easier to extend without dragging more brittle logic into core.

My take

What matters most

The biggest update is not Runway, not Lyria, not more locales. It is the continued move toward plugin-owned runtime behavior and stable structured prompts. That is the boring-looking work that compounds.

What I’d watch next

If this direction continues, the next meaningful leap will be tighter convergence between media tasks, session lifecycle, and plugin-owned UI surfaces. The primitives are now there.
