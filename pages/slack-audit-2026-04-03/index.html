🔍 Needs Research

3. replyToMode: "first" — threading behavior RESEARCH

Currently replyToModeByChatType.channel: "first", which threads all channel replies under the first message in a session. This may cause:

  • Cron output (daily brief, security reviews) threading under unexpected messages instead of appearing top-level
  • Cross-conversation confusion when multiple topics share a session
  • The "wrong channel" feeling when replies land in wrong threads

Options to research:

  • "off" — all replies top-level (cleanest for cron, but no threading)
  • "always" — always thread under the triggering message (more precise than "first")
  • Per-channel overrides (if supported)
  • Keep "first" but understand the trade-offs
🔬 Pending — will research OpenClaw docs and test options before recommending changes.

🟡 Open Warnings

4. thread.inheritParent: true may cause context bleeding WARNING

Thread sessions inherit the parent channel session's context. Combined with replyToMode: "first", this can create confused context when multiple threads are active in the same channel.

⏳ Recommendation: Set thread.inheritParent: false to isolate thread context. Low risk, reversible.
