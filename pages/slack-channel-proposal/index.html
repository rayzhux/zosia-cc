Research

Best Practices for Multi-Bot Slack

Synthesized from Slack's official AI app guidelines, channel organization research, and real-world patterns from teams running Linear + coding agents simultaneously.

Prefix-Based Naming

Use consistent prefixes so channels are discoverable and auto-sort in the sidebar. The industry standard: team-, proj-, sys-, bot-, feed-. Keep to under 10 prefixes total.

Bot Isolation

Give bots their own channels. Never let automated output flood human conversation channels. Create bot- or feed- prefixed channels for each integration's output. Humans subscribe to the ones they want.

@mention-Only in Human Channels

When multiple bots exist in a workspace, each bot should only respond when @mentioned in shared channels. This prevents the "every bot answers everything" problem. Slack's official AI app docs recommend this pattern.

Sidebar Sections

Slack doesn't have Discord-style categories, but every user can create sidebar sections (drag channels into custom groups). Design your channel names so they naturally group: all sys- channels together, all bot- together.

Tiered Notifications

Structure channels by urgency tier: Critical (all activity), Updates (mentions only), Digest (muted, check when needed). This maps directly to Slack's per-channel notification settings.

Thread-First Culture

All substantive discussion happens in threads. Top-level messages are announcements or triggers only. This keeps channels scannable and prevents cross-talk between humans and bots.

Key insight from Linear teams: Linear's Slack bot can get noisy fast — every issue update, comment, and status change generates a notification. Best practice is to route Linear notifications to a dedicated #feed-linear channel, then use Linear's built-in filtering to only send high-priority items. Same pattern applies to Devon — coding sessions generate lots of output that belongs in #bot-devon, not in #development.

Bot Strategy

Multi-Bot Coexistence Rules

With Zosia, Linear, Devon, and future third-party bots, you need clear ownership per channel. Here's how each bot should behave:

Bot Primary Channel Response Mode Behavior in Other Channels
Zosia #daily, #development Active — responds to all messages in her primary channels @mention only in #eng-* channels. Silent in #bot-* and #feed-* channels.
Linear Bot #feed-linear Feed-only — posts issue updates, never responds to messages Slash command (/linear) available everywhere. Notifications only in its feed channel.
Devon #bot-devon Active in its channel — accepts coding tasks, posts results @mention or slash command in #eng-* channels. Zosia stays quiet when Devon is handling a task.
Future Bots #bot-[name] or #feed-[name] Feed bots → feed channel. Interactive bots → bot channel. @mention only outside their home channel. Never auto-respond.

Zosia's behavior change: I'll configure per-channel system prompts so I know when to step back. In #bot-devon, I only respond if @mentioned. In #eng-coding, if Devon is handling something, I stay quiet unless you @zosia me directly. No more "every bot answers every message."

Setup

Recommended Sidebar Sections

After creating/renaming channels, organize your Slack sidebar into these sections. This is the closest equivalent to Discord categories:

1
⭐ Command Center

#daily, #briefings, #development, #alerts

2
🤖 Engineering

#bot-devon, #feed-linear, #feed-github, #webhook

3
⚙️ System

#sys-system, #sys-heartbeat, #sys-backups, #sys-token-usage — all muted by default

Scaling rule: When you add a new third-party bot, decide upfront: is it a feed (one-way notifications → #feed-[name]) or an interactive bot (accepts commands → #bot-[name])? This convention scales to any number of integrations without restructuring.

On the OpenClaw config side, I'll update per-channel system prompts for each new channel and set requireMention: true for Zosia in all #bot-* and #feed-* channels so I don't step on other bots' toes.
