Strategic Decision

Why Mem0 is the right foundation

You liked Mem0 for a reason — it's the most mature, well-documented memory engine with 50K+ GitHub stars, active development, and the exact dual-storage architecture (vectors + graph) that a Memory Palace needs. Here's the key decision tree:

✅ Mem0 OSS (self-hosted) — not Mem0 Platform (cloud)

Cloud ($249/mo for graph) is out. We self-host everything on your MacBook. Mem0 OSS is Apache 2.0 licensed, supports graph memory, and lets us choose our own LLM, embedder, vector store, and graph backend. We own every byte of data. Same codebase, full control.

Why Mem0

Battle-tested extraction

Mem0's two-phase pipeline (Extract → Update with ADD/UPDATE/DELETE/NOOP) is the most mature fact extraction engine available. Handles conflicts, dedup, and memory compression automatically.

Why Mem0

Dual storage built-in

Vector embeddings + graph relationships stored simultaneously. On retrieval, vector search narrows candidates while graph returns related entities — exactly what a Memory Palace needs.

Why Mem0

Pluggable everything

Swap LLM (OpenAI/Anthropic/Ollama), embedder, vector store (Qdrant/Chroma/20+), graph store (Neo4j/FalkorDB/Kuzu), and reranker independently. Future-proof by design.

Architecture

The complete stack on your MacBook

Component Choice Why Runs as
Memory Engine mem0ai (Python) Core library — fact extraction, memory CRUD, search orchestration Python library + REST API
Vector Store Qdrant (local) Default Mem0 vector store. On-disk at /tmp/qdrant → we'll move to ~/memory-palace/qdrant. No server needed — embedded mode. Embedded (in-process)
Graph Store FalkorDB 140ms p99 vs Neo4j's 46,900ms. Redis protocol, lightweight Docker container (~50MB). Per-user graph isolation built in. Drop-in Mem0 plugin. Docker container
Extraction LLM gpt-4.1-nano (default) → upgrade to gpt-4.1-mini Cheap, fast extraction. ~$0.001/document. We process once, cache forever. API call (OpenAI)
Embeddings text-embedding-3-small (1536d) Mem0 default, great quality/cost ratio. Can swap to local model later. API call (OpenAI)
Reranker Cohere rerank-english-v3.0 Significant search quality boost. 1000 free searches/month on free tier. API call (Cohere)
API Layer Mem0 REST API (FastAPI) Exposes all memory operations over HTTP. OpenClaw calls this locally. uvicorn on port 8200
OpenClaw Integration Custom OpenClaw skill + MCP server Natural language queries from Discord/WhatsApp hit the REST API. MCP for coding agents. OpenClaw skill

Why FalkorDB over Neo4j? Neo4j requires JVM, uses 1GB+ RAM idle, and the community edition has serious limitations. FalkorDB is a C-based graph engine with Redis protocol — starts in 2 seconds, uses ~50MB RAM, and is 335x faster at p99. The mem0-falkordb plugin is a single pip install + one line: register().

Entity Schema

What the graph knows about

Mem0's custom fact extraction prompt lets us define exactly what entities and relationships get stored. This is the domain model for your Memory Palace:

Entity Types

  • Person — name, role, company, relationship to Raymond
  • Company — name, industry, status, relationship (client/partner/prospect)
  • Project — name, status, key people, timeline
  • Meeting — date, attendees, key decisions, action items
  • Decision — what was decided, who decided, context, date
  • ActionItem — task, owner, deadline, status
  • Topic — recurring themes (AutoData pricing, Axxion integration, etc.)
  • Location — offices, venues, cities relevant to business

Relationship Types

  • WORKS_AT — Person → Company
  • REPORTS_TO — Person → Person
  • INTRODUCED_BY — Person → Person
  • ATTENDED — Person → Meeting
  • DECIDED — Person → Decision
  • ASSIGNED_TO — ActionItem → Person
  • DISCUSSED_IN — Topic → Meeting
  • PART_OF — Project → Company
  • LOCATED_IN — Company → Location
  • KNOWS — Person → Person (with context)

Custom extraction prompt example: "Extract people, companies, projects, decisions, and action items. Capture relationships like who-works-where, who-introduced-whom, who-decided-what. Include dates and context. Ignore small talk and pleasantries. Return JSON with facts array."

OpenClaw Integration

How Zosia uses the Memory Palace

New OpenClaw Skill: memory-palace

A custom skill that wraps the local Mem0 REST API. Natural language queries from any channel:

  • "Who did I last meet from AutoData?"
  • "What were the action items from my call with Terry?"
  • "Map all my touchpoints with Amin Kadrie"
  • "What decisions have we made about Axxion this quarter?"
  • "Who introduced me to [person]?"

Zosia calls memory.search() with hybrid vector + graph retrieval, gets both ranked memories AND entity relationships, assembles context.

Integration points

  • Meeting Intelligence — becomes a thin layer: "pull all memories for [attendee] + [company] before meeting"
  • Daily Brief — can reference relationship context ("You've met this person 3 times, last discussed X")
  • Cron ingestion — nightly cron syncs new emails, calendar events, transcripts into Mem0
  • Session memory — OpenClaw's existing MEMORY.md stays for operational state; Mem0 handles everything else
  • MCP server — mem0-mcp-server for coding agents (Claude Code, Codex) to access the palace
Implementation Roadmap

Five phases, each independently valuable

Foundation — Mem0 + FalkorDB + Qdrant on MacBook

Week 1. Install Mem0 OSS, spin up FalkorDB Docker container, configure Qdrant in embedded mode. Write the Mem0 config with FalkorDB graph store + Qdrant vector store + OpenAI LLM/embedder. Write and test the custom fact extraction prompt for your domain. Set up the REST API server on port 8200. Test with manual .add() and .search() calls.

Deps: Docker, Python 3.10+, OpenAI key (already have)

Ingestion Pipeline — Gmail + Calendar + Granola

Week 2-3. Build Python ingestion scripts for the three richest sources. Gmail: fetch threads via gog, convert to message arrays, feed to Mem0. Calendar: fetch events, extract attendees + descriptions. Granola: export transcripts, parse into conversation format. Each script is idempotent (tracks what's been processed). Run historical backfill — process everything you have.

Deps: Phase 1 complete, gog CLI, Granola MCP or muesli

OpenClaw Skill — Natural Language Interface

Week 3-4. Build the memory-palace OpenClaw skill. Wraps Mem0 REST API with natural language query understanding. Includes: search memories, get entity relationships, timeline queries ("what happened with X last month?"), people lookup ("tell me about [person]"). Meeting Intelligence refactored to query the palace instead of live-fetching everything.

Deps: Phase 1 + some data from Phase 2

Full Ingestion — Notion + Slack + OpenClaw Sessions

Week 4-5. Add remaining data sources. Notion pages and databases. Slack messages and threads. Historical OpenClaw session logs. Set up nightly cron job for incremental sync of all sources. Build the ingestion dashboard (how many memories, entities, relationships, last sync time).

Deps: Phase 2 pattern established

Intelligence Layer — Cross-Domain Reasoning

Week 6+. Advanced graph queries: relationship chains ("who connects me to Company X through fewer than 3 hops?"), temporal patterns ("what topics keep coming up in meetings with Y?"), network visualization via Obsidian export. Memory compression for frequently accessed facts. MCP server for external tool access. Backup strategy (R2 + encrypted snapshots).

Deps: Phases 1-4 complete, enough data for meaningful patterns

Risks & Mitigations

What could go wrong

Risk

FalkorDB port 6379 conflicts with Redis

If you ever run Redis locally, they'll clash. Mitigation: Run FalkorDB on port 6380 instead. One config change.

Risk

Extraction quality / noise

LLM extraction isn't perfect — it may miss entities or create duplicates. Mitigation: Custom extraction prompt with few-shot examples. Periodic manual review of graph in FalkorDB Browser. Dedup queries.

Risk

Docker dependency

FalkorDB needs Docker. Mitigation: Docker Desktop already on your Mac. FalkorDB is tiny (~50MB). Alternative: Kùzu (embedded, no Docker) if we want to eliminate this entirely later — but it's newer and less Mem0-integrated.

Risk

Data loss

Mitigation: Qdrant data is on-disk files. FalkorDB persists to Docker volume. Both backed up to R2 via existing nightly backup cron. Raw source data kept independently.
