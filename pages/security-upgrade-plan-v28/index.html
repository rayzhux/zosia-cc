3 Gap Analysis — What's Missing
10 gaps identified. 4 are quick fixes (< 5 min each). 4 are medium effort (script/doc changes). 2 are tradeoff decisions.
#GapRiskPriorityEffort
1 No skill baseline file
.skill-baseline.sha256 doesn't exist despite metric #12 checking it. Audit creates one on first run but it's never been seeded properly.		 Skill tampering undetected between audits P0 ~2 min · one command
2 Reports stored in /tmp/
Lost on reboot. v2.8 mandates $OC/security-reports/.		 Audit history wiped on restart P0 ~5 min · script edit
3 Config hash baseline stale
Generated Mar 11, config changed Mar 16. SEC-019 open.		 False alarm every night OR real tampering missed P0 ~1 min · one command
4 No known-issues exclusion list
No .security-audit-known-issues.json. Same false positives repeat in every Argus report (SEC-002 notes appended daily, SEC-005 etc.).		 False positives drown real alerts · wastes tokens P1 ~30 min · create JSON + update script
5 Missing secondary download interception
Our skill audit protocol checks for curl|sh but doesn't explicitly call out npm install, pip install, git clone, go get as secondary download vectors in the scan phase.		 Supply chain poisoning via indirect dependency pulls P1 ~15 min · doc update
6 Red line list incomplete
Missing: mkfs, wipefs, shred, block device writes, private key/mnemonic handling rule.		 Edge cases but real destructive potential P2 ~10 min · doc update
7 No post-upgrade baseline rebuild workflow
After npm i -g openclaw@latest or gateway config changes, no documented process to rebuild baselines.		 Stale baselines → false alerts or missed tampering P2 ~10 min · doc update
8 No report rotation
Reports accumulate indefinitely (or vanish with /tmp).		 Disk bloat or no retention P2 ~2 min · one line in script
9 Metric #13 missing (backup verification)
We have backup crons but the audit doesn't verify they ran. v2.8 includes Git DR as metric #13.		 Backup failures go unnoticed P3 ~20 min · script addition
10 Argus cron: no --light-context + expensive model
v2.8 recommends mid-tier model with --light-context. Our Argus runs GPT-5.4 + high thinking (~620s, high cost).		 Cost + potential behavioral deviation (v2.8 pitfall #2) P4 Decision · tradeoff review

6 Upgrade Plan — Prioritized Phases
Safety protocol: Each phase is atomic and independently testable. Script changes require unlock → edit → test → relock cycle (chflags nouchg / chflags uchg). All changes logged as [YELLOW].

P0 Phase 1 — Immediate Fixes (Today)

~15 minutes total. Zero-risk, high-value hardening.

  • Generate skill baseline
    find ~/.openclaw/workspace/skills -type f -not -path '*/.git/*' -exec shasum -a 256 {} \; | sort | shasum -a 256 > ~/.openclaw/.skill-baseline.sha256
    Resolves SEC-018. Metric #12 will pass clean tomorrow.
  • Rebuild config hash baseline
    shasum -a 256 ~/.openclaw/openclaw.json > ~/.openclaw/.config-baseline.sha256
    Resolves SEC-019. Metric #7 will pass clean tomorrow.
  • Move report path out of /tmp
    Unlock script → change REPORT_DIR to $OC/security-reports → add find "$REPORT_DIR" -name "report-*.txt" -o -name "report-*.json" -mtime +30 -delete at end → test → relock.
    Existing /tmp reports: migrate current reports with cp.
  • Fix version attribution
    Update docs/security-seal.md header to say "Originally based on pre-versioned guide (bd3e79e, Mar 5). Updated to v2.8 Beta alignment on Mar 18."

P1 Phase 2 — Structural Improvements (This Week)

~45 minutes. Biggest quality-of-life win for nightly reports.

  • Create known-issues exclusion list
    Write ~/.openclaw/.security-audit-known-issues.json seeded with confirmed recurring false positives from SEC-002, SEC-005, and any accepted findings.
    Update macos-security-audit.sh to read and apply exclusions (v2.8 pattern: annotate matching lines, adjust counts).
    Impact: Argus stops wasting tokens re-reporting accepted risks. Real new alerts stand out.
  • Enhance skill audit protocol with secondary download interception
    Update config/security-rules.md §Full-Text Scan to explicitly list secondary download vectors:
    Package managers (npm/pip/cargo/gem/go get), direct download (curl/wget/fetch/urllib), system bypass (python -m http.server, git clone), obfuscation (base64 -d | sh, eval + fetch).
    Add high-risk file type warnings: .so, .elf, .tar.gz, .whl, hidden dot-files.
    Add escalation rule: if secondary download detected → hard interrupt + red alert.
  • Update Argus cron prompt to reference exclusion list
    Audit cron reads the JSON natively (script-level filtering), so Argus sees pre-cleaned output.

P2 Phase 3 — Completeness (This Week)

~25 minutes. Fill remaining gaps for full v2.8 alignment.

  • Expand red line list
    Add to config/security-rules.md: mkfs, wipefs, shred, writing to block devices under /dev/.
    Add private key/mnemonic rule: "Strictly prohibited from asking for plaintext private keys or mnemonics. If found in context, immediately suggest clearing memory and block exfiltration."
    macOS-specific: diskutil eraseDisk already covered.
  • Document post-upgrade baseline rebuild
    Add to docs/security-seal.md §Maintenance:
    After openclaw upgrade → verify config integrity → rebuild config baseline → rebuild skill baseline → log as [YELLOW].
  • Fix audit script Remote Login metric
    Replace sudo systemsetup -getremotelogin with macOS-compatible check that works without TTY (SEC-013).

P3 Phase 4 — Additions (Next Week)

~30 minutes. New capabilities beyond current scope.

  • Add metric #13 — backup verification
    Add check to macos-security-audit.sh: verify last Git backup commit timestamp (workspace + config repos). Alert if >36h stale. Check R2 upload via last backup manifest. Non-blocking — failure logs as WARN, doesn't break other metrics.
  • Red Teaming validation drill
    Run the SlowMist Validation Guide (19 test cases) against our deployment. Document results. Identify any behavioral gaps in our model (Claude Opus) vs. v2.8 assumptions.

P4 Phase 5 — Tradeoff Decisions (Review)

No action until Raymond decides. Present options.

  • Argus cron model + context tradeoff
    Current: GPT-5.4 + high thinking (~620s, thorough, expensive).
    v2.8 recommendation: Mid-tier model + --light-context (~120s, cheaper, less behavioral deviation risk).
    Our context: Argus already has a restricted workspace (no SOUL.md, no memory). Behavioral deviation risk is lower than vanilla deployments. The findings tracker adds value that simpler models might miss.
    Options: (A) Keep current setup — working well. (B) Switch to Sonnet + normal thinking — save cost, probably fine. (C) Add --light-context only — reduce deviation risk without model change.
