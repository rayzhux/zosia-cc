Dedicated explainer on the difference in approach between our GPT and Opus iteration tracks

The two loops were not redundant. GPT behaved like a hard-nosed spec auditor: contradiction hunting, trigger-boundary cleanup, and final go/no-go judgment. Opus behaved like a systems designer with a knife between its teeth: generating new adversarial prompt families, spotting missing abstractions, and stress-testing the routing logic until the remaining failures were true ambiguity instead of sloppy policy.

1 — Executive read

GPT lane
Precision scalpel
  • caught exact contradictions between frontmatter and body text
  • refused to call the system done while one route still lied
  • excellent for final gating and trigger-boundary enforcement
  • less generative on new edge-case families
Opus lane
Chaos monkey with taste
  • invented stronger adversarial prompts and whole bug classes
  • turned isolated misses into named abstractions
  • excellent for widening eval space and discovering blind spots
  • slightly less crisp than GPT on strict “ship / don’t ship” boundaries
The loop worked because Opus made the map bigger and GPT made the map enforceable.

3 — Opus iteration profile

Ambiguous names, nonexistent versions, wrong-tool instructions, URL shortcut traps, frontmatter wording hazards.

5 — Spawn strategy that actually worked

Main agent

Orchestrator

Owned the artifact, decided next question, compared results across rounds.

GPT subagent

Auditor

Fresh session every round. Clean read of the current artifact instead of stale chat sludge.

Opus subagent

Critic

Fresh-session red team. Produced new failure classes instead of inheriting old assumptions.

Codex lane

Implementer

Applied the actual edits once the problem was clearly framed.

Why fresh sessions mattered
  • avoided context rot and stale rationalizations
  • reduced anchoring on previous wrong ideas
  • forced each evaluator to judge the current artifact, not the history of our confusion
  • made the loop feel more like independent review than recursive self-agreement

6 — What we learned

Lesson 1

Different models should play different roles

Builder, critic, grader, and archivist should not collapse into one voice if you care about truth.

Lesson 2

Fresh-session looping beats giant-context marination

The external artifact should carry state; the evaluator should stay fresh.

Lesson 3

Named abstractions beat one-off prompt patches

Once a bug class has a name, it can become policy instead of folklore.

Final synthesis

The reusable pattern is already visible: Opus for widening the threat model, GPT for tightening the contract, Codex for applying the patch, and fresh spawned sessions to keep every round honest. That is the real engine hiding inside this “routing session.”
