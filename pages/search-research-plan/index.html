Principles

Rules that emerged across 17 rounds

1
Substance beats verbs
"Research how Supabase handles realtime" → doc-lookup. "Research the AI market" → Exa. Route by what the user needs, not how they phrase it.
2
Exa finds pages. web_fetch reads them.
Discovery and extraction are different jobs. Never use web_fetch to search. Never use Exa to read a known URL.
3
Decompose compound prompts
Split multi-need sentences and route each sub-need independently. Don't let one URL or product name collapse everything.
4
User source preferences are substantive
"Skip the docs — what are devs saying?" is a source redirect, not a verb. Respect it. Different from "research X" where the verb misleads.
5
Frontmatter must match body
Skill selection happens from descriptions first. If frontmatter contradicts body rules, routing breaks at the trigger layer.
6
Quality is the only routing signal
Cost never appears in the decision path. Route by which tool gives the best answer.

5-Bullet Summary

1. Two skills, one boundary: doc-lookup = one product's official docs. exa = everything else.

2. Route by substance, not verbs: "Research how Supabase handles realtime" → doc-lookup. "Research the AI market" → Exa.

3. Four tiers: Discovery (Exa search) → Extraction (web_fetch) → Synthesis (deep_search) → Deep Research (deep_researcher pro).

4. Decompose compound prompts — split multi-need sentences and route each independently.

5. Quality over cost — route by best results, never by cheapest tool.

Production-ready. 5-10% residual risk on genuinely ambiguous prompts — model judgment territory, not rule failures.
