💓 Heartbeat: The Context Hog

The heartbeat system is the single biggest context consumer per invocation. Here's the chain:

→
+ gog calls
+ cron list
+ VPS checks
= 15-25 tool calls

Every 30 min (or whenever heartbeat fires), that 10 KB file gets read into context. It's the most-read file in the entire system, and it's huge — calendar IDs, Discord channel IDs, JSON templates, escalation matrices, state schemas. Much of this is reference material that could be a script.

🛠️ Recommendations — Making Zosia Lighter

1. Shrink heartbeat-instructions.md
At 10.2 KB / 256 lines, this is the heaviest per-invocation file. Move calendar IDs and Discord channel IDs into a JSON config file that the heartbeat script reads directly. Keep instructions to ~3 KB of prose. The JSON templates for CV2 cards can be examples, not full specs repeated 4x.
Savings: ~7 KB per heartbeat tick (fires 20-30x/day)
2. Delete IDENTITY.md
92-byte stub that says "See SOUL.md". Loaded every single session. Delete it — OpenClaw's boot-md hook will just skip it if missing.
Savings: 1 file read eliminated per session
3. Deduplicate TOOLS.md ↔ topics/tech-setup.md
TOOLS.md has provider details, VPS info, and web scraping docs that are also in tech-setup.md. Make TOOLS.md a routing table only — what tool to use for what. Move the "how it works" docs into tech-setup.md (Layer 3, searched not loaded).
Savings: ~2 KB from Layer 1 boot load
4. Trim topics/incidents.md
18 KB of incident history — the largest topic file. Archive resolved incidents older than 30 days. Keep only the lesson learned (which goes in lessons.md anyway). This file gets pulled into context on any memory_search about past problems.
Savings: ~12 KB from Layer 3 search results
5. Consolidate safety rules
Safety info lives in 3 places: AGENTS.md (Security Seal), security-rules.md, and MEMORY.md (Critical Safety Rules). AGENTS.md should say "red/yellow line rules in config/security-rules.md" without repeating the patterns. MEMORY.md should drop the safety section entirely (it's in AGENTS.md).
Savings: ~800 bytes from Layer 1
6. Review visual-explainer size
At 38 KB, this is the single largest SKILL.md. It's loaded every time you ask for a diagram. The full Mermaid theming guide, CSS patterns, and template references could move to sub-files that are read conditionally (already partially done with references/).
Savings: ~20 KB per visual-explainer invocation
7. HEARTBEAT.md → inline in system prompt
HEARTBEAT.md is 119 bytes that says "read the heartbeat file". This indirection adds a file read for zero value. If the heartbeat trigger text is already in the system prompt (it is), this file is redundant. Delete it.
Savings: 1 fewer file loaded at boot

📎 Notes

  • SOUL.md is sacred. 6.1 KB is not cheap, but it's the personality core. Don't touch it.
  • topics/ files are well-layered — they only enter context via memory_search, not boot. The concern is their size when they DO get pulled in.
  • Skills are loaded one-at-a-time by design. The skill registry in L0 (~5 KB of descriptions) is the tax; actual SKILL.md only loads on match. The 38 KB visual-explainer is the outlier.
  • Argus (set up today) is a separate agent, not a boot-loaded file. Its context is isolated — no impact on Zosia's boot weight.
  • The system prompt (L0) is ~25 KB and managed by OpenClaw, not user-editable. The skill descriptions add ~5 KB to it (34 skills × ~150 bytes each).
