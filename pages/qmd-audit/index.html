What is QMD

QMD is the brain behind your memory search

Every time you ask me something about past conversations, decisions, or context — I search through your memory files using QMD (by Tobi Lütke, Shopify founder). It's a local AI search engine that runs three models on your Mac's GPU:

  • 1. Embedding Model
    Turns text into numerical vectors (like GPS coordinates for meaning). "Dubai real estate" and "property in UAE" end up near each other in vector space.
  • 2. Query Expansion Model
    Takes your search and generates alternate phrasings. If you search "Charlie server", it also searches "Singapore VPS", "remote deployment", etc.
  • 3. Reranking Model
    Takes the initial results and re-scores them by deeply reading each one against your query. Catches nuances that keyword matching misses.

What Was Broken

89% of your memory had no vector embeddings

When I ran qmd status on your actual memory index, I found 100 files indexed but only 11 had vectors. The other 89 files were searchable by keywords only — no semantic understanding.

This means if you asked "what's the Singapore server situation?" and the file said "Charlie VPS deployment" without the word "Singapore", the vector path would miss it entirely. Only keyword matches would work.

Why did this happen?

QMD indexes files in two steps: first it catalogs them (fast), then it generates vector embeddings (slower — requires GPU). The embedding step wasn't keeping up with new files being added. Every daily note, session log, and topic file that got created was cataloged but never embedded.

The old version (1.0.8) also had a bug where the reranker would produce garbage scores on documents longer than 2048 tokens — meaning even the 11 files that had vectors could get incorrectly ranked.

Version Upgrade — 1.0.8 → 1.1.5

Key improvements in the new version

  • 1.1.5 Intent parameter
    Disambiguates vague queries. "Performance" could mean web speed, team health, or sports. With intent="web page load times", the entire search pipeline focuses correctly.
  • 1.1.2 GPU auto-detection rewrite
    Replaced 220 lines of manual Metal/CUDA detection with automatic GPU probing. More reliable on your M2 Mac.
  • 1.1.2 Reranking performance fixes
    Deduplicates identical content before reranking, caps parallel GPU contexts to prevent VRAM exhaustion.
  • 1.1.1 Reranker truncation fix
    Long documents now get properly truncated at 2048 tokens instead of producing garbage scores. This was silently corrupting rankings.
  • 1.1.0 Structured query documents
    Can now combine keyword search + semantic search + hypothetical answers in a single query for precision retrieval.
  • 1.1.0 BM25 phrase matching & negation
    Exact phrase search with quotes ("rate limiter") and exclusion (-sports) for disambiguation.

Blocked — Needs OpenClaw Update

Three features we can't use yet

These are QMD features that require OpenClaw (the gateway software) to update its integration code. We have the features installed locally, but OpenClaw doesn't know how to use them yet.

HIGH Intent parameter

The biggest potential win. When I search memory, OpenClaw doesn't tell QMD why I'm searching. So "performance" returns a mix of web speed, team, and sports results. With intent, every search would be contextually steered.

MED Structured queries

OpenClaw passes a single text string. QMD 1.1.0+ supports typed queries (keyword + semantic + hypothetical combined) for precision recall.

LOW MCP daemon mode

QMD can run as a persistent background server, keeping GPU models warm between searches (~10s vs ~16s latency). OpenClaw spawns a fresh process each time.
