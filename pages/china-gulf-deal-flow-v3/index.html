What v0.2 got wrong

  1. The "06:25 → 09:20" pseudo-cadence was cosplay. A cron runs once. Those internal stages don't exist as scheduled events. v0.3 has one runbook with wall-clock budgets, fail-fast exits, and a 25-minute ceiling.
  2. 10–14 Kimi calls + 6–8 Exa calls in one session was fantasy-sized. Token budget, parsing overhead, citation validation, and dedup blow up before cost does. v0.3 caps total searches at 10.
  3. "Gulf official + CN source = confirmed" was naive. WAM repost of a MOFCOM press release is not independent confirmation — it's the same ink twice. v0.3 uses source-of-origin rules: filing/IR > counterparty newsroom > ministry primary > PR distributor never alone.
  4. The 5-question filter let MOU theater through. "Named actor + corridor thesis + Dhow lane" already scores 3 with no money, license, or asset. v0.3 has hard kill gates: new fact, named actor, material action.
  5. The 70-source list was operationally undifferentiated. Some are daily deal-flow, some are quarterly background, some (Xueqiu, Zhihu, Autohome retail) are noise. v0.3 splits them into Daily / Verification / Weekly / Do-not-ship.
  6. 09:20 GST is before the deals land. A-shares close 11:00 GST, HKEX 12:00 GST, Gulf PR midday-pre-lunch. v0.3 runs at 12:30 GST.
  7. One-session cron has zero memory. v0.2 said "14-day dedup" but had no ledger. v0.3 specifies a persisted JSON ledger at ~/.hermes/data/china-gulf-ledger.json.
  8. No failure-mode handling. Silent degradation makes the post look complete when Kimi or Exa actually died. v0.3 logs degradation and tags Discord posts when applicable.

§ 01 · Architecture shift

Watchlist-first. Discovery is the accent.

v0.2 was a discovery engine that ran broad queries and hoped to find named actors in the noise. v0.3 inverts: a watchlist of 60 priority actors drives 70% of daily searches with deterministic, cheap, high-signal queries. Free-form discovery only fires for the remaining slots — and only after the watchlist pass produces nothing.

Daily searches against the 60-actor watchlist, 3 CN cohorts × top names + 3 Gulf cohorts × top names + 1 lane-rotating cohort. Cheap. Reliable. Misses unknown unknowns.

SCAN lane · 20%

§ 03 · The 12:30 GST runbook

One session, hard caps, fail fast.

Cron fires once at 12:30 GST. Everything below happens in one LLM session with explicit budgets and abort exits. No pseudo-cadence, no inter-stage scheduling.

12:30 GST · single-session runbook

model: openai-codex/gpt-5.5 · target wall-clock 15min · ceiling 25min · abort & summarize on tool failure

§ 04 · Confidence by source-of-origin

Two appearances ≠ two confirmations.

The biggest v0.2 bug: counting outlets instead of independent originating artifacts. WAM republishing a MOFCOM press release is the same ink twice. v0.3 ranks artifacts by their distance from the actual source-of-truth — and only a genuinely independent second artifact can lift confidence to confirmed.

● Confirmed

Two independent originating artifacts from different sides of the deal. E.g. HKEX filing + counterparty newsroom; or company IR + Gulf SWF press release.

● Reported

One credible originating artifact without counterparty confirmation. E.g. ministry primary alone, or major business press standalone reporting.

● Watch

Echo / chatter / weak signal only. Goes to ledger but doesn't ship to Discord unless explicitly marked "strategic exception" with a one-line reason.

§ 05 · Editorial gate

Three hard kills before scoring.

v0.2's "≥3 of 5 questions" was a soft filter that let MOU theater through. v0.3 puts three mandatory gates first. If any fails, the candidate is killed. Only survivors get scored on the soft questions.

Hard kill 1

New fact

Something material changed since the ledger's last entry on this event_id: new amount, new license, new plant location, new counterparty, new asset, new commercial milestone, new regulatory approval.

Hard kill 2

Named actor

Specific named Chinese company and specific named Gulf counterparty (entity, ministry, fund, free zone, distributor). "A Chinese delegation" is not an actor. "Several Saudi investors" is not an actor.

Hard kill 3

Material action

Money committed, order volume, license issued, plant or site, JV entity, deployment, tender award, or signed commercial contract. "Exploring cooperation", "delegation visited", "roadshow held", "framework MOU" default to weekly background unless tied to named pipeline.

Soft scoring

5Q on survivors only

Thesis fit · Dhow/WAG lane · proof vs. pipeline · delta vs. yesterday · actionability for Raymond. Used for ranking, not gating. Top 3-5 ship.

§ 07 · Persisted ledger & Kimi output spec

The thing v0.2 forgot to specify.

A one-session cron has zero memory. The ledger is the only way 90-day soft / 14-day hard dedup can actually work. Every shipped, killed, and follow-up event gets written.

Ledger · ~/.hermes/data/china-gulf-ledger.json
// one entry per event_id { "event_id": "lenovo-alat-riyadh-hub-2024-05", "actors_cn": ["Lenovo / 联想"], "actors_gulf": ["Alat", "PIF"], "country": "SA", "asset": "Riyadh manufacturing hub", "action_type": "investment", "amount_usd": "2B convertible", "first_seen": "2024-05-29", "last_seen": "2026-04-25", "sources": [ {"url": "...", "type": "hkex_filing"}, {"url": "...", "type": "company_ir"} ], "confidence": "confirmed", "status": "shipped", "shipped_dates": ["2024-05-30"], "next_watch": "2026-08-01" }
Kimi-cn JSON contract · per result
// scripts/kimi --json must produce this { "title_cn": "...", "url": "...", // required, non-empty "source": "36氪出海", // required "published_at": "2026-04-24", "claim": "one-line factual", "actors": ["BYD", "PIF"], "is_original_source": true, "why_relevant": "WAG lane · proof" } // missing url or source → discard
Dedup behavior

14-day hard: exact same article URL or near-duplicate headline → silently dropped. 90-day soft: same event_id with no new fact → flagged as follow-up, ledger updated, doesn't ship. 90-day soft + new fact: ships as "Update" with explicit delta vs. last entry.

§ 08 · Failure modes

Silent degradation kills trust.

If Kimi or Exa fails mid-session, the post must say so — not look complete. Three explicit degradation states.

⚠ Kimi unavailable

Run Exa-only. Discord post footer: CN-native leg unavailable. Confidence ceiling drops to reported for this run.

⚠ Exa partial / failed

Run Kimi + RSS only. Don't post unless ≥2 items have non-Kimi citations (RSS or direct extract). Footer: Gulf web leg degraded.

⚠ Both failed

RSS only. If RSS produces ≥2 candidates passing the editorial gate: ship with RSS-only run footer. Otherwise log silently.

⚠ Wall-clock > 25min

Abort to summary mode: ship whatever passed the gate up to that point, footer notes aborted at <step>. Update ledger with partial state.
