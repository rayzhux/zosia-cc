Vercel vs Cloudflare Pages

Can Cloudflare fully replace Vercel for zosia-pages and future projects? Feature-by-feature comparison based on current docs and your existing stack.

Bottom Line

Yes — Cloudflare Pages can replace Vercel entirely for your use case. Static HTML pages with git-triggered deploys, custom domains, and access control. Cloudflare does everything Vercel does here, plus native Access integration you're already paying for. The only thing you'd lose is Vercel's serverless functions ecosystem — which you don't use.

What You'd Gain by Moving
Cloudflare Access for free — the exact UX you asked for. You authenticate via Google, friends get email OTP, bots get nothing. No $20/mo Vercel Pro needed.

Unified stack — DNS, CDN, Access, R2 backups, WAF, and hosting all in one dashboard. You already manage Cloudflare for DNS and R2.

Unlimited bandwidth — Vercel caps at 100GB/mo on Hobby. CF Pages is unlimited.

Per-path access rules — could make some pages public and others private. Vercel can't do this.
What You'd Lose
Nothing material for zosia-pages. It's static HTML — no Next.js, no serverless functions, no Vercel-specific features in use.

For WAG (cc-wag-me.com) — if it uses Next.js server-side features, moving it is more complex. Cloudflare's Next.js support via OpenNext works but isn't as seamless as Vercel's native integration. Recommendation: keep WAG on Vercel, move zosia-pages to Cloudflare. Or move both if WAG is purely static.
Migration Steps (zosia-pages → Cloudflare Pages)

~15 minutes of work

  1. Create CF Pages project — connect rayzhux/zosia-pages GitHub repo in the CF dashboard → Workers & Pages → Create → Connect to Git
  2. Configure build — no build command needed (static HTML). Output directory: / (root)
  3. Add custom domain — e.g., pages.dhowholding.com (or any domain on your Cloudflare account)
  4. Set up Access — create an Access application on that domain. Policy: allow your email + Google OAuth as identity provider
  5. Update share.sh — change deploy from git push (same) or use wrangler pages deploy
  6. Rename vercel.json — convert cleanUrls + headers to _headers / _redirects files
  7. Test — verify pages load, Access prompt works for incognito, your Google login bypasses
  8. Sunset Vercel project — delete after confirming everything works
