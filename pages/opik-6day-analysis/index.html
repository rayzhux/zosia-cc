Root Cause Analysis — The 3 Real Problems
Problem 1 — Recurring 6/6 Days

web_fetch: Speculative URL Fetching

The single biggest error source across the entire 6-day window. Every single day has web_fetch errors — mostly 404s and 403s from blindly hitting URLs that either don't exist or are behind auth/firewalls.

  • Mar 9: 19 errors / 171 calls (11.1%) — 17 were "404 with security wrapper"
  • Mar 10: 22 errors / 174 calls (12.6%) — 17 x 404, 4 x 401, 1 DNS failure
  • Mar 11: 7 errors / 15 calls (46.7%) — 7 x 401 security wrapper
  • Mar 12: 0 errors / 16 calls (0%) — clean day, low volume
  • Mar 13: 7 errors / 38 calls (18.4%) — 5 x 404, 2 x 403
  • Mar 14: 7 errors / 36 calls (19.4%) — 5 x 404, 2 x 403

Root cause: The doc-lookup skill and cron-spawned agents guess at documentation URLs (e.g. docs.resend.com, Postmark pages) without verifying they exist first. The "security wrapper" errors are OpenClaw's own safety envelope on external content — the URLs themselves are returning 404/403/401.

Problem 2 — Recurring 4/6 Days

browser: Stale References & Timeouts

Browser errors appeared on 4 of 6 days and accounted for the second-highest error volume. Two distinct failure modes:

  • Stale tab/target IDs: 24 errors across Mar 9–11. Agent tries to interact with a tab ID from a previous snapshot that's already gone.
  • UI action timeouts: 5 errors across Mar 9–13. Clicking or waiting for elements that never appear (8–10s timeouts).
  • Element not found: 6 errors on Mar 10. Referencing e207, e269, e437 etc. from stale snapshots.

Root cause: Agents use browser automation for tasks that could be done via API/exec/web_fetch. When they do use browser, they don't re-snapshot before acting. The skill eval runs on Mar 9–10 generated most of this noise — but the pattern (use API paths instead of browser) is a real design fix.

Problem 3 — Recurring 4/6 Days

message: Bad Target / Missing Params

Discord message errors keep appearing — "unknown channel", "guildId required", "query required", "userId required", bad CV2 block types. Most are from cron-spawned agents that don't have the right channel context.

  • Mar 14: 10 errors / 183 calls (5.5%) — 8 x "unknown channel"
  • Mar 11: 5 errors / 59 calls (8.5%) — mixed param errors
  • Mar 13: 2 errors / 64 calls (3.1%) — channel type mismatch
  • Mar 10: 1 error / 25 calls (4%)

Root cause: Cron job payloads and sub-agents reference Discord channel IDs that are wrong or use actions not supported on the target channel type. This is a configuration problem, not a runtime problem.

Recommendations — Prioritized
Priority 1 · High Impact · Low Effort

Build a verified URL cache for doc-lookup

44 of the 62 web_fetch errors (71%) are the same pattern: hitting a guessed URL → 404/401/403. Create a simple docs-cache/verified-urls.json mapping (product → known-good URL). The doc-lookup skill checks this map before fetching. If the URL isn't cached, try llms.txt or the product's canonical docs domain first. This eliminates the #1 error source across all 6 days.

  • File: ~/.openclaw/workspace/config/verified-doc-urls.json
  • Skill: Update doc-lookup/SKILL.md to check map first
  • Expected impact: –70% of web_fetch errors overnight
Priority 2 · High Impact · Medium Effort

Stop using browser where API/script paths exist

35 browser errors across 4 days. Most were from using browser automation for tasks that have direct API or CLI equivalents (Opik has a REST API, Discord has the message tool, etc). The browser should be reserved for tasks that genuinely need it — JS-rendered pages with no API alternative, interactive forms, OAuth flows.

  • Audit skills that spawn browser actions — replace with API calls
  • When browser IS needed: always re-snapshot before acting on element refs
  • Expected impact: –80% of browser errors, faster execution
Priority 3 · Medium Impact · Low Effort

Fix cron job Discord channel targets

9 "unknown channel" errors on Mar 14 alone. Cron-spawned agents are using stale or wrong channel IDs. Audit all cron jobs that post to Discord and verify the channel IDs match real channels in the guild.

  • Run: cron list → check each job's target channel
  • Cross-reference with message channel-list
  • Expected impact: eliminates message targeting errors entirely
Priority 4 · Medium Impact · Trivial Effort

Install ripgrep & alias python → python3

16 errors across 4 days from missing rg and python. These are trivially fixable environment setup items.

  • brew install ripgrep
  • Add alias python=python3 to ~/.zshrc or install python-is-python3
  • Expected impact: eliminates two recurring error fingerprints
Priority 5 · Cost Reduction · Medium Effort

Route routine cron work to cheaper models

GPT-5.4 is eating 92.5% of spend. Many cron jobs (daily brief, token report, Opik review) are routine summarization — they don't need GPT-5.4. Route these to Opus (30x cheaper per token in practice) or Sonnet/Flash for the mechanical parts. Keep GPT-5.4 for interactive sessions and complex reasoning tasks.

  • Audit cron jobs: which ones specify a model? Which inherit the default?
  • Set explicit model overrides on routine cron payloads
  • Expected impact: –40-60% cost reduction ($6-10/day saved)
