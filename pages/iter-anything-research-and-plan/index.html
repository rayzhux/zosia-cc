Research synthesis · reusable iteration framework

From Ralph + autoresearch + skill-creator
to an iter-anything skill

Research result + final plan for a generalized iteration engine that can improve skills, workflows, setups, prompts, policies, and code

The key conclusion is simple: don’t build a cute looping prompt. Build a real framework with artifact types, evaluation contracts, role separation, fresh-session spawning, measurable stopping rules, and external memory. Ralph gives us clean-session mechanics. Autoresearch gives us experimental discipline. Skill-creator gives us a working benchmark/review loop. The missing layer is the generalized schema.

1 — Research synthesis

Finding

Loops need bounded state

  • fresh context works better than endlessly accumulated chat history
  • artifact files, summaries, and benchmarks should carry memory
Finding

Loops need measurable improvement

  • without a real score, iteration becomes storytelling
  • cheap evaluation cycles beat giant expensive reflection blobs
Finding

Loops need role separation

  • builder, critic, and grader should not collapse into one model voice
  • fresh specialized subagents keep the loop honest
The generalized loop is: define target → define baseline → define evals → generate candidate → test → grade → distill → patch → repeat.

3 — Autoresearch: the scientific spine

Editable surface

One thing changes

Autoresearch wins because the editable surface is bounded. The analog for us is: one artifact under improvement per loop.

Cheap experiment

Short eval cycle

A loop only compounds if each round is cheap enough to run many times. That means compact evals, not giant theatrical review rounds.

Real metric

Keep / discard

Valuation has to be explicit: tests, pass rate, latency, cost, human preference, robustness. Otherwise the loop is just aesthetics in drag.

4 — Skill-creator: why we are not starting from zero

02

Eval set

Generate realistic prompts/tasks that stress the artifact.

03

Baseline vs candidate

Run both in parallel instead of grading one in a vacuum.

04

Benchmark + review

Quantitative assertions plus human qualitative review.

05

Improve + repeat

Rewrite based on evidence, not vague preference, then rerun.

What skill-creator already proves
  • we already know how to compare baseline vs candidate
  • we already know how to collect human feedback and quantitative assertions
  • we already know how to run multiple fresh subagents in parallel

What it does not yet generalize: artifact schema, role schema, grader schema, and stop rules across non-skill domains.

6 — Recommended build plan

Phase 1

Schema first

Define the artifact, eval, grader, budget, and round-summary JSON before writing the skill body.

Phase 2

v1 artifact types

Support skill, prompt, workflow, and code task first. Don’t boil the ocean.

Phase 3

Spawn roles

Default to builder + critic + grader fresh subagents every round.

Phase 4

Report layer

Generate baseline vs candidate review pages, benchmark deltas, and “ship / continue / stop” decisions.

Phase 5

Expand carefully

Add research, policy, and setup optimization only after the core loop is stable.

Bottom line

The right build is not “Ralph but for everything” and not “skill-creator but longer.” It is a hybrid: Ralph’s clean iteration mechanics + autoresearch’s measurable experiment discipline + skill-creator’s benchmark / review workflow + our GPT/Opus role split. Build the schema first, then the skill. Otherwise we’ll create a clever-sounding mess.
