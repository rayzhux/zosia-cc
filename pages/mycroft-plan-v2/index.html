02 · The Key Insight

Bindings ≠ Posting Rights

The Mental Model That Changes Everything

This is the single most important concept for your multi-agent setup:

  • Bindings control who responds to human messages in a channel. "If Raymond posts here, which agent handles it?"
  • Cron payloads can post to any channel regardless of bindings. The message tool uses the shared Discord bot token.

This means: Mycroft doesn't need any channel bindings. It posts to #reddit, #x-gcc, #daily-news via cron payloads. But if you ask a question in #reddit, Zosia answers — because she has the conversational context to discuss the data.

What Mycroft actually is: A background worker with its own workspace, lighter system prompt, and isolated failure domain. It exists as an agentId for cron jobs — not as a channel presence. Zosia stays your universal interface. Mycroft is invisible to you unless a cron output post says otherwise.

04 · The #daily Triage Problem

When You Drop an Idea, Who Picks It Up?

The Problem

You drop ideas in #daily. Some are about OpenClaw config (Zosia's domain). Some are pure research tasks (could be Mycroft). Some start as one and become the other. You shouldn't have to think about routing — that's the agent's job.

The Solution: Zosia Triages, Always

#daily stays 100% Zosia-bound. She reads every thread. Here's her decision tree:

  • Interactive / personal / OpenClaw: Zosia handles directly. "Set up Mycroft config," "prep me for my meeting," "what's our token spend?" — all Zosia.
  • Pure research task: Zosia still starts the thread (creates it, writes the opener). Then she can delegate the heavy lifting to Mycroft via sessions_send or spawn a subagent under Mycroft's context. The research output comes back and Zosia posts it in the thread.
  • Ambiguous: Zosia handles it herself. When in doubt, the chief of staff does it. No routing confusion.
Why not auto-route #daily to Mycroft for research? Because you want one front door. If Mycroft handled some threads and Zosia others, you'd need to remember who's who. Zosia-as-triage means you never think about it. She's smart enough to delegate when the task is mechanical. And since Mycroft is cron-only in v1, the delegation would use sessions_send to spawn isolated work anyway.

Future: The #research Channel (v2)

When Mycroft proves itself on crons, you can create a #🔬-research channel bound directly to Mycroft. Drop pure research tasks there — no triage needed. Mycroft picks them up, runs deep searches, posts results. Zosia doesn't touch it.

This is the natural evolution: #daily for ideas you want to discuss, #research for tasks you want executed.

No bindings. Mycroft has no channel bindings. It posts via cron payloads using the shared bot token. All human messages go to Zosia via the existing guild-wide catch-all.

Step 3: Update 10 Cron Jobs

// For each of the 10 migrating cron jobs: cron update --jobId "<job-id>" --patch { "agentId": "mycroft" } // That's it. No other changes needed because: // - Payloads already use absolute paths to scripts // - message tool works with any agentId // - Model is already set per-job in the payload
Zero bindings needed. This is the simplest possible multi-agent config. Add one agent object, update 10 agentId fields. No routing rules, no channel remapping, no permission changes. Zosia's existing guild-wide binding handles everything.
08 · Build Sequence

One Step at a Time

Phase 1: Foundation SAFE

Create ~/.openclaw/workspace-mycroft/. Write SOUL.md, AGENTS.md, MEMORY.md, TOOLS.md. No config changes. No restart.

Risk: Zero. It's just files.

Phase 2: Register Agent RESTART

Add Mycroft to agents.list via config.patch. Gateway restart. Verify Zosia still works on all channels — Mycroft is registered but has no crons yet.

Risk: Low. New agent with no bindings can't break existing routing.

Phase 3: Token Report First SAFE

Reassign Token Usage Report to Mycroft. Simplest cron, runs once daily, easy to verify. Watch one full cycle.

Risk: Minimal. If it fails, revert agentId to "main".

Phase 4: Backups + Opik SAFE

Migrate Daily Backup, Weekly Archive, Opik Daily, Opik Weekly. These are self-contained scripts with no skill dependencies.

Phase 5: Intelligence Pipelines WATCH

Migrate Reddit daily/weekly, X daily, Daily Brief. These use skills with data directories. Watch for path resolution issues (should be fine since cron payloads use absolute paths).

Phase 6: Security Review WATCH

Migrate Nightly Security Review. Uses thinking:high — verify Mycroft handles extended thinking correctly.

Phase 7: Observe & Tune ONGOING

Run for one full week. Watch: all 10 crons fire? Correct channels? Zosia's context lighter? No regressions? Then consider v2 additions like #research channel.

What Success Looks Like

  • 10 crons run under Mycroft with zero regression in output quality
  • Zosia's system prompt is lighter — fewer skills, fewer cron instructions
  • A failed Reddit pipeline at 5:30 AM doesn't contaminate your 9 AM DM with Zosia
  • You never notice the split. The Discord channels look exactly the same.
  • When you ask Zosia "what's trending on Reddit?", she reads #reddit and tells you — same as today
